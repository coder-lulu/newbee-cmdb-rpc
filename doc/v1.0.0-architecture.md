## 📋 服务概述

CMDB服务是企业级运维管理系统的核心组件，负责管理所有IT配置项的全生命周期。基于go-zero微服务框架构建，采用Ent ORM进行数据建模，提供灵活的资产建模引擎、关系管理、自动发现和变更追踪能力。

### 核心职责
- **配置项管理**: IT资产的全生命周期管理
- **关系建模**: 复杂资产依赖关系的建模和维护
- **动态属性**: 灵活的资产类型定义和属性模板系统
- **自动发现**: 基于Agent的资产信息自动采集和同步
- **变更追踪**: 完整的配置变更历史和版本管理
- **影响分析**: 变更影响面分析和风险评估

## 🔧 核心模块设计

### 1. 配置项管理模块 (CI Management)

基于old-project-doc的CMDB实现，该模块负责所有配置项的基础管理功能：

**核心功能**:
- CI创建、更新、删除、查询
- CI状态管理 (运行中、维护中、已停用等)
- CI生命周期管理 (规划、开发、测试、生产、退役)
- CI批量操作和数据导入导出
- CI访问权限控制

**技术实现**:
```go
// CI核心数据结构
type ConfigurationItem struct {
    ID              int64     `json:"id"`
    CITypeID        int64     `json:"ci_type_id"`        // 配置项类型ID
    Name            string    `json:"name"`              // 配置项名称
    DisplayName     string    `json:"display_name"`      // 显示名称
    Status          int       `json:"status"`            // 状态：1-运行中，2-维护中，3-已停用
    Environment     string    `json:"environment"`       // 环境：dev/test/prod
    Owner           string    `json:"owner"`             // 负责人
    BusinessUnit    string    `json:"business_unit"`     // 业务单元
    Attributes      JSONText  `json:"attributes"`        // 动态属性JSON
    CreateTime      time.Time `json:"create_time"`
    UpdateTime      time.Time `json:"update_time"`
    CreateBy        string    `json:"create_by"`
    UpdateBy        string    `json:"update_by"`
}
```

### 2. 动态建模引擎 (Modeling Engine)

这是CMDB的核心创新，支持灵活的资产类型定义：

**模型定义能力**:
- CI类型动态定义 (服务器、网络设备、应用系统等)
- 属性模板配置 (基础属性、扩展属性)
- 属性验证规则 (必填、格式、取值范围)
- 属性间依赖关系 (条件显示、联动更新)
- 继承关系设计 (父子类型继承)

**技术实现**:
```go
// CI类型定义
type CIType struct {
    ID              int64          `json:"id"`
    Name            string         `json:"name"`              // 类型名称
    DisplayName     string         `json:"display_name"`      // 显示名称
    Icon            string         `json:"icon"`              // 图标
    ParentID        *int64         `json:"parent_id"`         // 父类型ID
    IsAbstract      bool           `json:"is_abstract"`       // 是否抽象类型
    DefaultTemplate string         `json:"default_template"`  // 默认模板
    Attributes      []AttributeDef `json:"attributes"`        // 属性定义
    UniqueKeys      []string       `json:"unique_keys"`       // 唯一键组合
}

// 属性定义
type AttributeDef struct {
    Name         string                 `json:"name"`          // 属性名
    DisplayName  string                 `json:"display_name"`  // 显示名
    Type         string                 `json:"type"`          // 数据类型
    Required     bool                   `json:"required"`      // 是否必填
    DefaultValue interface{}            `json:"default_value"` // 默认值
    Options      []string               `json:"options"`       // 可选值
    Validations  []ValidationRule       `json:"validations"`   // 验证规则
    Dependencies []AttributeDependency  `json:"dependencies"`  // 依赖关系
}
```

### 3. 关系管理引擎 (Relationship Engine)

管理配置项之间的复杂关系：

**关系类型**:
- **物理关系**: 包含、连接、安装在
- **逻辑关系**: 依赖、使用、监控
- **业务关系**: 服务于、归属于、负责人

**关系特性**:
- 方向性：单向/双向关系
- 传递性：关系的传递计算
- 约束性：关系的建立约束
- 时效性：关系的生效时间

```go
// 关系定义
type CIRelation struct {
    ID           int64     `json:"id"`
    FromCIID     int64     `json:"from_ci_id"`     // 源配置项ID
    ToCIID       int64     `json:"to_ci_id"`       // 目标配置项ID
    RelationType string    `json:"relation_type"`  // 关系类型
    Direction    int       `json:"direction"`      // 方向：1-单向，2-双向
    Weight       float64   `json:"weight"`         // 关系权重
    Properties   JSONText  `json:"properties"`     // 关系属性
    EffectTime   time.Time `json:"effect_time"`    // 生效时间
    ExpireTime   *time.Time `json:"expire_time"`   // 失效时间
    CreateTime   time.Time `json:"create_time"`
    CreateBy     string    `json:"create_by"`
}
```

### 4. 自动发现引擎 (Discovery Engine)

基于Agent的自动化资产发现和同步：

**发现能力**:
- 服务器硬件信息 (CPU、内存、磁盘、网卡)
- 操作系统信息 (版本、补丁、配置)
- 中间件信息 (数据库、Web服务器、应用服务器)
- 网络设备信息 (交换机、路由器、防火墙)
- 应用信息 (进程、服务、端口)

**发现策略**:
```go
// 发现任务定义
type DiscoveryTask struct {
    ID           int64                `json:"id"`
    Name         string               `json:"name"`         // 任务名称
    Type         string               `json:"type"`         // 发现类型
    Targets      []DiscoveryTarget    `json:"targets"`      // 发现目标
    Schedule     string               `json:"schedule"`     // 调度配置 (cron)
    Enabled      bool                 `json:"enabled"`      // 是否启用
    LastRunTime  *time.Time           `json:"last_run_time"` // 上次执行时间
    NextRunTime  *time.Time           `json:"next_run_time"` // 下次执行时间
    Config       DiscoveryConfig      `json:"config"`       // 发现配置
}

// 发现结果处理
type DiscoveryResult struct {
    TaskID       int64          `json:"task_id"`
    TargetID     string         `json:"target_id"`
    Status       string         `json:"status"`        // success/failed/partial
    DiscoveredCIs []DiscoveredCI `json:"discovered_cis"` // 发现的配置项
    Errors       []string       `json:"errors"`        // 错误信息
    CreateTime   time.Time      `json:"create_time"`
}
```

### 5. 变更追踪引擎 (Change Tracking Engine)

提供完整的配置变更历史和版本管理：

**变更追踪功能**:
- 字段级别的变更记录
- 变更前后值对比
- 变更原因和审批流程
- 变更影响面分析
- 批量变更的事务管理

```go
// 变更记录
type ChangeRecord struct {
    ID           int64               `json:"id"`
    CIID         int64               `json:"ci_id"`          // 配置项ID
    ChangeType   string              `json:"change_type"`    // 变更类型：create/update/delete
    FieldChanges []FieldChange       `json:"field_changes"`  // 字段变更详情
    Reason       string              `json:"reason"`         // 变更原因
    Approver     string              `json:"approver"`       // 审批人
    ImpactLevel  string              `json:"impact_level"`   // 影响级别：low/medium/high
    RollbackData JSONText            `json:"rollback_data"`  // 回滚数据
    CreateTime   time.Time           `json:"create_time"`
    CreateBy     string              `json:"create_by"`
}

// 字段变更详情
type FieldChange struct {
    Field    string      `json:"field"`     // 字段名
    OldValue interface{} `json:"old_value"` // 原值
    NewValue interface{} `json:"new_value"` // 新值
}
```

## 📊 数据模型设计

### 数据模型优化说明

> **重要**: 基于对 old-project-doc 数据模型的深度分析，我们发现原有设计存在过度分表、性能问题等多个问题。  
> 详细的数据模型优化方案请参考: [数据模型优化设计 v1.1.0](./v1.1.0-optimized-model.md)

3. **cmdb_cis** - CI实例表 (统一JSON属性存储)

#### 🔗 关系管理表 (1个)

#### 📝 属性管理表 (1个)

### 核心优化特性

#### 1. 统一属性存储
```sql
-- 原设计：5个分散的值表
cmdb_value_texts, cmdb_value_integers, cmdb_value_floats, 
cmdb_value_datetimes, cmdb_value_json

-- 优化后：统一JSON存储
CREATE TABLE cmdb_cis (
    id BIGINT PRIMARY KEY,
    attributes JSON, -- 所有动态属性统一存储
    -- MySQL 8.0+ 支持JSON索引和查询优化
    INDEX idx_attr_hostname ((JSON_EXTRACT(attributes, '$.hostname'))),
    INDEX idx_attr_env ((JSON_EXTRACT(attributes, '$.environment')))
);
```

#### 2. 智能查询优化
```sql
-- 支持复杂JSON查询
SELECT * FROM cmdb_cis 
WHERE JSON_EXTRACT(attributes, '$.cpu_cores') > 8
  AND JSON_EXTRACT(attributes, '$.environment') = 'prod'
  AND JSON_CONTAINS_PATH(attributes, 'one', '$.monitoring.enabled');
```

#### 3. 灵活的类型定义
```json
{
  "attribute_schema": {
    "hostname": {"type": "string", "required": true, "unique": true},
    "cpu_cores": {"type": "integer", "min": 1, "max": 128},
    "environment": {"type": "enum", "options": ["dev", "test", "prod"]},
    "monitoring": {
      "type": "object",
      "properties": {
        "enabled": {"type": "boolean", "default": true},
        "agent_version": {"type": "string"}

    }
  },
  "unique_constraints": [
    ["hostname", "environment"],
    ["ip_address"]
  ]
}
```

## 📈 性能优化

### 缓存策略

1. **CI类型缓存**: CI类型定义长期缓存，TTL=24小时
2. **热点CI缓存**: 访问频繁的CI信息，TTL=1小时  
3. **关系链缓存**: 关系查询结果缓存，TTL=30分钟
4. **查询结果缓存**: 复杂查询结果缓存，TTL=15分钟

```go
// 缓存键设计
const (
    CacheKeyCIType   = "cmdb:ci_type:%d"           // CI类型缓存
    CacheKeyCI       = "cmdb:ci:%d"                // CI详情缓存  
    CacheKeyRelation = "cmdb:relation:%d:%s"       // 关系缓存 (CI_ID:direction)
    CacheKeyQuery    = "cmdb:query:%s"             // 查询结果缓存 (query_hash)
)
```

### 数据库优化

1. **读写分离**: 主库写入，从库查询
2. **分表分库**: 按CI类型和时间分片
